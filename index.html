PROJECT 01 — FLAGSHIP

Tavessa

RESTAURANT OPERATING SYSTEM · FULL-STACK PLATFORM

A restaurant management platform where Guest, Staff, Kitchen and Owner each get their own interface — all running on one FastAPI and PostgreSQL backend with real-time synchronization. A guest scans a table QR code and orders; the kitchen display lights up; staff serve; the owner watches it all happen live.

V1.0.0 DEMO RELEASE — LIVE

ReactTypeScriptFastAPIPostgreSQLWebSocketsTailwind CSS
LIVE DEMO GITHUB REPOSITORY

THE PROBLEM

A restaurant floor runs on disconnected fragments — paper orders, shouted kitchen updates, bills tallied by hand. Guests, kitchen, staff and owners each see a different version of the truth.

THE SOLUTION

One platform, four role-specific interfaces, a single source of truth. Every order state change — Placed → Accepted → Cooking → Ready → Served — propagates to every screen in real time.

ARCHITECTURE

Modular monolith. React / TypeScript / Vite / Tailwind / shadcn-ui frontend; FastAPI with SQLAlchemy 2.0; PostgreSQL with Alembic migrations; WebSocket channels per role; cash-only payments confirmed in person by staff.

KEY FEATURES

  • QR table sessions — guests order from their own phone, no app install
  • Live kitchen display with real-time ticket flow
  • Bill generation, equal split, cash confirmation and receipts
  • Owner dashboard with a full audit log

ENGINEERING & VERIFICATION

Built stage by stage with a full test pyramid — 377 backend tests, a frontend Vitest suite and 81/81 end-to-end checks on the golden path. The complete flow was verified live on the deployed demo (restaurant “Zaika”): table menu → order → kitchen → served → bill → cash → receipt. Frozen as the v1.0.0 Demo Release in November 2026.

PROJECT 02 — FLAGSHIP

SignSpeak Telecom

ACCESSIBILITY · AI VIDEO COMMUNICATION

An AI-powered bidirectional video-call platform bridging Deaf and hard-of-hearing participants with hearing participants in the same call. One side signs — the platform reads it and speaks. The other side speaks — the platform captions it live. Neither side has to leave the conversation.

DEPLOYED — VERCEL · RENDER · LIVEKIT CLOUD

Next.jsTypeScriptFastAPIMediaPipePyTorch LSTMWhisper ASRLiveKit / WebRTC
GITHUB REPOSITORY

THE PROBLEM

Video calls assume everyone can hear and speak. For Deaf and hard-of-hearing people, a call with a hearing participant usually means a third-party interpreter or falling back to typed chat — the conversation itself is never shared.

THE SOLUTION

A two-way bridge inside one call: sign language → text → speech in one direction, and speech → text → live captions in the other, so both participants communicate in the mode natural to them.

ARCHITECTURE

Next.js (App Router) + React + TypeScript frontend; Python FastAPI backend; OpenCV and MediaPipe extract 21 hand landmarks per frame, sequenced for a PyTorch LSTM recognizer; Whisper-family ASR transcribes speech; Piper TTS voices the signed side; LiveKit carries the WebRTC rooms; PostgreSQL stores accounts and rooms.

RECOGNITION PIPELINE

  • 10-sign vocabulary: Hello, Yes, No, Help, Thank You, Emergency, Please, Sorry, Good, Goodbye
  • 21 hand landmarks × 30-frame sequences
  • Utterance-based caption stream for the hearing side

AN HONEST NOTE ON ACCURACY

A trained model ships with the project, but its real-world recognition accuracy has not been formally measured — so no figure is quoted here. The hosted deployment (Vercel frontend, Render backend and database, LiveKit Cloud) was completed and verified end to end in November 2026.

PROJECT 04 — MACHINE LEARNING

Mental Health Predictor

PYTHON · SCIKIT-LEARN · FASTAPI

A regression study of how student lifestyle signals — sleep, screen time, stress, study and activity — relate to a self-reported mental-health score. A stacked ensemble served by a FastAPI backend, with a What-If habit simulator and scenario presets like “Exam Crammer” and “Balanced Rhythm”.

PROJECT 05 — RECOMMENDER SYSTEMS

MovieVerse

PYTHON · TF-IDF · FASTAPI + STREAMLIT

A content-based movie recommendation engine. Give it a title you loved; it vectorizes overviews and genres with TF-IDF, ranks by cosine similarity, and blends in popularity and rating so the results feel curated rather than merely similar. Posters, cast and trailers come from the TMDB API.

score = 0.75·similarity + 0.15·popularity + 0.10·(rating / 10)

Content-based only — no collaborative filtering. TMDB's own recommendations lead the results, with the local TF-IDF engine filling the list. Output is a ranked set of similar titles, each with a match percentage.
